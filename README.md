# Credit Scoring Model Validator

**Можно ли верить цифре AUC?** AUC 0.73 — это хорошо или плохо? Сама цифра не скажет:
модель могла быть обучена с утечкой, предсказания — плохо калиброваны, а портфель —
измениться к моменту внедрения.

Этот инструмент честно отвечает на три вопроса о вашей скоринговой модели:

1. **Качество** — ранжирование, калибровка, достаточность данных;
2. **Стабильность** — дрейф скора и признаков, качество по периодам;
3. **Надёжность** — доверительные интервалы, число дефолтов.

Он принимает **результаты скоринга** (`y_true`, `y_score`, признаки, даты) и возвращает
отчёт с 40+ проверками, тремя сводными карточками и интерактивными графиками.
Если что-то не проверено — честно говорит «не проверено», а не подставляет число.

> Исследовательский инструмент. Не система одобрения кредитов. Обучение модели здесь не живёт:
> валидатор проверяет скоры, а не создаёт их.

---

## Демо (одной командой)

```bash
docker compose up
# API  → http://localhost:8000  (документация /docs)
# UI   → http://localhost:8501  → кнопка «Демо» → «Запустить проверку»
```

Локально без Docker:

```bash
pip install -e ".[dev]"
uvicorn src.api.app:app --reload        # API
streamlit run frontend/app.py           # UI
```

**Путь новичка:** файл (или «Демо») → подтверждение найденных столбцов → запуск →
автопереход на отчёт с тремя карточками. Без вопросов о seed и периодах —
сервер сам выберет референс (ранние 70% по дате) и число bootstrap-повторов.

---

## Что выдаёт отчёт

- **Три карточки**: качество / стабильность / надёжность со статусом = худший внутри
  (`норма` / `внимание` / `не проверено`).
- **«Требует внимания»** — конкретные замечания с объяснением.
- **«Не проверено»** — что не удалось рассчитать и почему (честно, без выдуманных чисел).
- **5 интерактивных графиков (Plotly)**: распределение скора по классам, калибровка по
  децилям, метрики по периодам, PSI с наложением распределений, доля дефолтов по периодам.
- **HTML (основной) / PDF / JSON** — один и тот же отчёт в трёх форматах.


## Архитектура

```
┌─────────────┐   CSV/Parquet    ┌─────────────────────────────────┐
│  Streamlit  │ ───────────────▶ │  FastAPI                         │
│  (2 экрана) │ ◀─────────────── │  · загрузка + маппинг (+вопросы) │
└─────────────┘   summary+charts │  · очередь задач (JobRunner)     │
                                │  · TTL-очистка данных (24 ч)     │
                                └──────────────┬──────────────────┘
                                               │ run_full_validation
                                ┌──────────────▼──────────────────┐
                                │  src/validation (ядро)            │
                                │  метрики → MetricResult(status)   │
                                │  → ValidationReport → HTML/PDF/JSON│
                                └──────────────────────────────────┘
```

- **Ядро** (`src/validation`) — вся логика, работает и как библиотека без API.
- **API** (`src/api`) — тонкий слой: валидация запроса, задачи, хранилище, TTL.
- **UI** (`frontend`) — тонкая оболочка: карточки из `summary`, графики из результата.
- Правило: если метрика не определена (один класс, мало данных) — статус
  `not_computable` и `value=None`, а не число.

## Тесты

```bash
pytest -q                       # весь набор (200+ тестов)
pytest tests/test_validation_synthetic.py -q   # Шаг 1: дефекты → статусы
pytest tests/test_ui_app.py -q                # Шаг 7: «Демо → отчёт»
```

CI (GitHub Actions) запускает синтетику и AppTest отдельными шагами.


## Реальный кейс: Lending Club 2007–2011

`python scripts/prepare_lending_club.py` — загрузка, бинаризация `loan_status`,
два скора (LogisticRegression «во времени» и `int_rate` как ранговый балл),
прогон с признаками-утечками. Отчёты: `data/lending_club/report_*.html`.

**Что валидатор нашёл:**

1. **Утечку** — и показал, что одной проверки мало. `recoveries` и `total_pymnt` дают
   IV ≥ 0.5, но одномерный AUC флагает только `recoveries`. `total_pymnt` ловится
   только IV. Вывод: нужна связка проверок, а не одна.
2. **Смещение калибровки при нормальном ранжировании.** AUC = 0.66 (умеренно),
   но средний прогноз 0.171 против фактических 0.148 дефолтов — модель систематически
   завышает риск.
3. **Ранговый балл нельзя интерпретировать как вероятность.** Для `int_rate`
   (`score_kind=score`) Brier/LogLoss/калибровка честно ушли в `not_computable`,
   а PSI предсказаний = 0.442 — значительный дрейф ставок между периодами.
4. **Незрелость target — там, где она есть.** В 2007–2011 доля статуса Current = 0
   (все кредиты погашены): падение доли дефолтов 26% → 14% — это ужесточение скоринга
   после кризиса, а не незрелость, и инструмент честно говорит «признаков незрелости нет».
   На полном диапазоне 2007–2018 (Current растёт до 32→62%) детектор «Зрелость target»
   срабатывает: ratio 0.13 → warning.

## Второй кейс: Taiwan Credit Card (30 000 строк, без дат)

`python scripts/prepare_taiwan.py` — out-of-fold вероятности LR. Без дат секция
«Во времени» честно уходит в «не проверено», а на 300 строках интервал AUC растёт
в 11 раз (0.014 → 0.16) и появляется предупреждение о достаточности. Прогон прошёл
без правок кода пакета — контракт полный.


## Чего инструмент не делает

- Не восстанавливает чужую модель и не утверждает, что восстановил её.
- Не считает SHAP без доступа к модели (`model=` с методом `predict_proba`).
- Не оценивает качество на периодах без фактических исходов.
- Доверительные интервалы учитывают только случайность выборки, но не смену периода
  или популяции.
- Не строит «эталонного challenger» и не сравнивает с ним.

Подробности: `docs/validation_package.md`.

## Данные

Загруженные через UI/API данные **не хранятся бессрочно**: действует TTL-очистка
(по умолчанию 24 часа, `VALIDATOR_DATASET_TTL_HOURS`). Демо-данные и отчёты —
в `data/`; сырые Lending Club (1.6 ГБ) в git не попадают.

## Деплой

Проект состоит из двух частей: **FastAPI** (вся логика, загрузка, очередь) и
**Streamlit** (тонкий UI). Они разворачиваются вместе (`docker compose up`).

Для облачного размещения:
- **FastAPI** — на Railway/Render (Python 3.11), команда `uvicorn src.api.app:app`.
- **Streamlit** — на Streamlit Community Cloud, переменная окружения
  `API_URL=http://<адрес API>` или secret `API_URL = "https://<публичный адрес API>"`.
  Streamlit Cloud запускает только UI: API нужно развернуть отдельно; `localhost`
  внутри облака не указывает на локальный компьютер.
- `runtime.txt` фиксирует Python 3.11 — без него облако ставит Python 3.14,
  где reportlab 3.5.x не собирает C-расширение. Плюс в `pyproject.toml`
  `reportlab>=4.0` (рабочая версия на новых Pythons).
